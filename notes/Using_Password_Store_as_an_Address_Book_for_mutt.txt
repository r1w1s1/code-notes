USING PASSWORD STORE AS AN ENCRYPTED ADDRESS SOURCE FOR MUTT

OVERVIEW

Password Store (pass) is commonly described as a password manager, but
its design is more general: it stores arbitrary plain text encrypted
with GPG.

This document describes using pass as an encrypted alias source for
mutt, replacing static alias files or dedicated address book tools.
Aliases are decrypted at runtime and kept only in memory.


REFERENCE DOCUMENT

This document assumes an existing pass + GPG setup.

For full details on installation and configuration, see:

https://git.sr.ht/~r1w1s1/code-notes/blob/main/notes/Password_Store_with_Git_Guide.txt


DESIGN GOALS

- keep address data encrypted at rest
- rely only on mutt, pass, and GPG
- avoid plaintext files
- preserve mutt’s native alias behavior


BACKGROUND

mutt does not require an address book. It only consumes alias
definitions of the form:

    alias shortname Full Name <email@example.com>

These are normally stored in plaintext and sourced at startup. pass
already provides encrypted storage and plaintext output on demand.


ADDRESS STORAGE

Aliases are stored as a single pass entry.

Example path:

    email/address

The entry content is plain mutt alias syntax.


EXAMPLE ENTRY

Create the entry if it does not exist:

    pass insert email/address

Addresses can be added incrementally using:

    pass edit email/address

Example contents:

    alias john   John Doe <john@example.com>
    alias sbo    SlackBuilds <slackbuilds-users@slackbuilds.org>
    alias work   Ricardson <r@company.com>

The data is configuration, not a secret, but remains encrypted at rest.


MUTT CONFIGURATION

In ~/.muttrc, source the aliases directly from pass:

    source "pass show email/address |"

At startup, mutt reads aliases from standard output. No plaintext files
are written to disk.


USAGE

While composing mail:

    To: john<Tab>

Expands to:

    John Doe <john@example.com>


GPG AGENT BEHAVIOR

gpg-agent caches the decrypted key in memory, avoiding repeated
passphrase prompts. Aliases are loaded once per mutt startup.


LIMITATIONS

This approach intentionally avoids address book features such as
interactive browsing or automatic sender capture. Users requiring those
features may prefer tools such as abook.


CONCLUSION

Password Store is a general-purpose encrypted text store, not limited to
passwords. Using it as a mutt alias source provides encrypted-at-rest
configuration with minimal tooling, predictable behavior, and full user
control.
